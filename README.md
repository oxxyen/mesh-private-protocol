> ⚠️ **Этот репозиторий предназначен исключительно для разработчиков команды. Не для публичного использования.**

**Mesh** — это внутренняя кодовая база для разработки анонимного P2P-мессенджера с акцентом на безопасность, локальное хранение и минимальную уязвимость.  
Проект использует C/C++ для основной логики, SQLite для хранения данных, Python — для вспомогательных инструментов: сборки, тестирования, обфускации и отладки.

---
```
## 📁 Структура проекта
├── src/ → Основной код сервера (C)
├── assets/ → Код клиентской части (C++, Qt / GUI)
├── p2p_messenger/ → Тестовый P2P-сервер + клиент + протокол сигнализации
├── tests_scripts/ → Автотесты и утилиты для проверки
├── trash/ → Временные файлы, эксперименты, черновики
├── meshctl.py → Главный скрипт управления: сборка, запуск, отладка
├── brootfrouce.py → Скрипт обфускации исходного кода (для защиты IP)
├── mesh_tester.py → Автоматизированные тесты (интеграционные, юнит-тесты)
├── compile.sh → Быстрая сборка (обёртка над CMake)
├── Makefile → Сборка под Linux/Unix
├── CMakeLists.txt → Главный CMake-файл проекта
├── README.md → Этот документ
└── .env → Переменные окружения для разработки
```
---

### ⚙️ Скрипты
В корне репозитория находятся ключевые Python-скрипты для автоматизации повседневных задач команды:

- **`meshctl.py`** — Универсальный контроллер проекта: сборка, запуск сервера, отладка, очистка и управление окружением.  
- **`brootfrouce.py`** — Обфускация C/C++-кода для защиты интеллектуальной собственности при внешней передаче.  
- **`mesh_tester.py`** — Автоматизированные тесты: проверка P2P-соединений, целостности шифрования, работы с SQLite и устойчивости к ошибкам.

## 🛠️ Технологии

| Компонент           | Используется для |
|---------------------|------------------|
| **C++17 / C99**     | Ядро сервера, сетевое взаимодействие, криптография |
| **SQLite3**         | Локальное хранение сообщений, метаданных, ключей |
| **Python 3.9+**     | Управление проектом (`meshctl.py`), обфускация (`brootfrouce.py`), тестирование (`mesh_tester.py`) |
| **Qt (опционально)**| GUI-клиент в `assets/`     |
| **SignalProtocol**  | Signal protocol(libsignal-protocol-c) |
| **libsodium / OpenSSL** | Шифрование сообщений, генерация ключей, аутентификация |

> 💡 Все компоненты должны собираться локально. Никаких внешних облачных сервисов или зависимостей не должно быть в финальной сборке.

## 🚀 Запуск и управление проектом

### 🔧 Основной инструмент: `meshctl.py`

Скрипт для управления жизненным циклом проекта(все описано и понятно как использовать):

```bash
python3 meshctl.py --help
``` 

### 🔐 Обфускация кода: `brootfrouce.py`

Скрипт **`brootfrouce.py`** предназначен для защиты исходного кода от реверс-инжиниринга, статического анализа и несанкционированного копирования.

- Применяется **перед релизными сборками** или при передаче кода внешним сторонам (например, QA-команде или партнёрам).
- Выполняет переименование переменных, удаление комментариев, искажение структуры кода без изменения логики.
- Работает с директориями на входе и генерирует обфусцированную копию в указанной выходной папке.

```bash
python3 brootfrouce.py --help
```
### 🖥️ Архитектура

#### 📌 `src/` — Серверная часть  
Основная логика сервера, написанная на C/C++.

- **`server.c`** — главный сервер(ОСНОВНОЙ ФАЙЛ): слушает порты, управляет сессиями и маршрутизацией сообщений, signal protocol, защита от ддос атак, шифрование, генерция токена, хранение локальных данных, безопасность.   
- **`server.h`** — заголовочные файлы: объявления функций, структур данных и интерфейсов.  
- **`MeshServer.hpp`** — C++-классы и интерфейсы  
- **`server_wrapper.h`** — обёртки для FFI (Foreign Function Interface), позволяющие вызывать серверные функции из Python или других языков.

---

#### 📌 `assets/` — Клиентская часть  
GUI-клиент на базе Qt (C++).

- **`chatclient.cpp`**, **`mainwindow.cpp`** — реализация логики чата и графического интерфейса.  
- **`main.cpp`** — точка входа клиентского приложения.  
- **`ChatClient.pro`** — проектный файл для Qt Creator (содержит зависимости и настройки сборки).

---

#### 📌 `p2p_messenger/` — Тестовый модуль  
Прототип P2P-взаимодействия для отладки сигнального протокола и сетевой логики.

- **`p2p_messenger.c.c`**, **`main.c`** — упрощённые реализации P2P-клиента и сигнального сервера.  
- **`network.c`** — работа с сокетами, обработка подключений, реализация сигнального протокола.  
- **`store.c`** — временное хранение сообщений в памяти или на диске.  
- **`p2p_messenger.db`** — тестовая SQLite-база для эмуляции локального хранилища.

> 🔁 Этот модуль используется **только для разработки и тестирования** — не входит в финальную сборку.
